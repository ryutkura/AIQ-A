# AIQandA システム概要・使い方ガイド

このディレクトリ（リポジトリ）は、ITエンジニアリングや数学などの質問（QandA）とAIによる解説を蓄積し、Obsidian等のグラフビューで有機的に繋げるためのパーソナルナレッジベースです。
AIエージェントを最大限に活用するための「自動連携システム」が組み込まれています。

---

## 使い方

### 1. QandAの蓄積
AIに質問をすると、AIが自動的に文脈を判断し、適切なフォルダ（`programming`, `math` など）の適切なMarkdownファイルに追記、あるいは新規作成してくれます。
人間が「このファイルに保存して」と細かく指示・管理する必要はありません。全てAIに任せることができます。

### 2. 画像（スクショ）を使った質問
数式やエラー画面など、言葉で説明しづらいものはスクリーンショットを使って質問できます。いちいちファイルに名前をつけて保存する手間は不要です。

1. `Win + Shift + S` で画面の必要な部分を切り取る（クリップボードにコピーされる）
2. AIに向かって「今のクリップボードの画像を解説して」「この画像を見て」と指示する
3. AIが裏側で自動的に抽出ツール（`tools/get_clipboard.py`）を起動し、画像を読み込んで解説してくれます。
※一時ファイルはAIが自動で破棄するため、ゴミデータは一切残りません。

### 3. ナレッジグラフの更新
ノートが増えてきたら、AIに「キーワードをリンク化して」と頼むだけで、重要単語（「[[MVC]]」「[[参照渡し]]」など）が自動的にObsidianのリンク記法（二重角括弧）に変換されます。
これをObsidianで開くことで、関連知識が蜘蛛の巣状に可視化されます。

読み始めるときは **[[moc/ホーム|ホーム]]** から入ってください。領域ごとの入口とダッシュボードがあります。

## フォルダ構成

| フォルダ | 役割 |
| --- | --- |
| `math` / `programming` / `machine_learning` / `infrastructure` / `linux` / `software_engineering` | QandAの本体。トピック別 |
| `troubleshooting/` | **ハンズオンの沼ログ。** エラーと、そこから抜けるまでの記録 |
| `concepts/` | 概念ノート。複数の記事から参照される語を実ノート化したもの。**グラフのハブ** |
| `moc/` | 領域ごとの入口（Map of Content）とダッシュボード。**自動生成物** |
| `inbox/` | 分類に迷う走り書き。後で振り分ける |
| `publish/` | Qiita/Zenn 投稿用の書き出し先。**正本はVault側** |
| `templates/` | ノートの雛形（Obsidianのテンプレート機能から挿入） |
| `image/` | スクリーンショットなどの添付ファイル |
| `tools/` | 裏方スクリプトと設定ファイル |

`concepts/` が無いと、「[[行列]]」のような語へのリンクは全て「存在しないノート」を指すだけで、
**ノート同士は一切繋がりません。** ここがグラフの心臓部です。

## メンテナンスコマンド

全てのツールは**既定では書き込みません**。プレビューで内容を確認してから `--write` を付けてください。

| コマンド | 用途 |
| --- | --- |
| `python tools/link_keywords.py` | 現状診断（リンク解決率・破損箇所） |
| `python tools/link_keywords.py --link --write` | キーワードをリンク化 |
| `python tools/make_concepts.py --write` | 2記事以上から参照された語を `concepts/` に追加 |
| `python tools/add_frontmatter.py --write` | frontmatter の無いノートに付与 |
| `python tools/make_moc.py --write` | `moc/` を再生成 |

ノートを追加したあとは、上から順に流すのが基本の運用です。

## ハンズオンで詰まったとき

エラーで詰まった話は `troubleshooting/` に残します。雛形は `templates/沼ログ.md`（Obsidianの「テンプレートを挿入」から使えます）。

ファイル名は日付を前に置きます — 沼は概念ではなく**イベント**だからです。

```
troubleshooting/docker/2026-08-09_port-already-allocated.md
```

**絶対に省略しないでほしいのが3つ**あります。

1. **エラーの全文** — 要約しないこと。後日同じエラーに遭遇した時、**エラー文をそのまま全文検索して過去の自分に辿り着く**のが最大の使い道だからです。
2. **試したことの表** — 「何を試したか」だけでなく「なぜそう考えたか」と「なぜダメだったか」を書きます。これが無いと次回また同じ袋小路に入ります。
3. **「なぜ沼ったか」** — 一番価値がある欄です。「知らなかった」で終わらせず、*どんな思い込みが判断を誤らせたか* を書きます。

解決しなかった場合も `status: unsolved` で残してください。「試したがダメだった手」の記録は再挑戦時に最も効きます。

AIに聞きながら作業していれば、解決した時点でAIが自動でこの形式のノートを作ります（`AI_INSTRUCTIONS.md` に指示済み）。

## Qiita / Zenn に投稿する

```bash
python tools/export_for_publish.py math/LinearAlgebra/LU_decomposition.md --target zenn --write
```

`--target qiita` でQiita形式にもなります。手で `publish/` に書かず、必ずこのツールを通してください。

* QiitaもZennもObsidianのリンク記法を**レンダリングしません**。ツールが自動で除去します。
* frontmatter の仕様が両者でまったく違うため、それぞれの形式で生成します。
* **Qiitaはローカル画像を参照できません。** 画像がある記事は、Qiitaにアップロードして発行されたURLに差し替える必要があります（ツールが該当画像を一覧表示します）。

## システム構成（AIエージェントとの連携）

このディレクトリには、AIエージェントが「人間の手を煩わせることなく自律的に動く」ための仕組みが用意されています。

* **`AI_INSTRUCTIONS.md`**
  AIエージェントに読ませるための「絶対遵守ルール（取扱説明書）」です。有能なAIは起動時にこれを読み込み、「このディレクトリでの振る舞い方（画像の読み方やファイルの作り方）」を自律的に理解します。

* **`tools/` フォルダ**
  * `get_clipboard.py`: クリップボードから画像を抽出し、AIが読める一時ファイルに変換する。
  * `link_keywords.py`: リンクの診断・付与・修復・解除。
  * `keywords.txt`: リンク対象の語の定義。**語を増減させたい時はここを編集する。**
  * `make_concepts.py` / `concept_defs.md`: `concepts/` のスタブ生成と、その定義ソース。
  * `add_frontmatter.py`: frontmatter の付与（日付は git 履歴から復元）。
  * `make_moc.py`: `moc/` の生成。

この仕組みにより、他のCLIツールや新しいAIエージェントを導入した際にも、シームレスな体験が引き継がれます。
