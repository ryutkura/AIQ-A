# スキルの画面は「HTMLファイル直開き」と「localhost」のどちらがよいか

## 質問

practice-lab（演習・ドリルを作るエージェント用スキル）の画面は、HTML ファイルで完全にローカルなのか。
localhost でサーバーを動かした方が「ちゃんとしている」のか。個人がポチポチ勉強するだけなら完全ローカルで十分なのか。

## 今の practice-lab の仕組み

**完全ローカル。** サーバーもネット接続も使わない。

1. `lab.py build` / `lab.py drill today` が、問題のデータを HTML の中に**埋め込んで**1つのファイルを作る
2. 本人はそれをダブルクリックで開く（アドレスバーは `file:///...`）
3. 途中の回答はブラウザの localStorage に一時保存される
4. 最後に「JSONを保存」でファイルを書き出し、`results/` に置く。**記録の正本はこのファイル**

## 2つのやり方の比較

| | HTMLファイル直開き（今の方式） | localhost のサーバー |
| --- | --- | --- |
| 始め方 | ダブルクリックだけ | 毎回サーバーを起動する（止めると開けない） |
| 結果の保存 | ブラウザのダウンロード → 手で `results/` に移す | ページから直接 `results/` に書き込める |
| 配布のしやすさ | 高い。Python とブラウザがあれば動く | ポート番号の衝突、起動手順の説明が増える |
| 壊れにくさ | 高い。動くものが少ない | プロセスの管理が要る |
| 安全面 | 外から触られる口がない | 同じPCの他のプログラムからアクセスできる口が開く（`127.0.0.1` に限定する必要がある） |
| 向いている用途 | 1人で使う教材、配布するスキル | 複数人で使う、DB や API とつなぐ、画面を頻繁に更新する |

「オシャレさ」は localhost かどうかでは決まらない。見た目は HTML と CSS の作り方で決まるので、直開きでも同じ見た目にできる。

## 結論

**1人で勉強する道具なら、完全ローカルが正解寄り。** 配布するスキルなら、なおさら依存が少ない方がよい。

localhost にする価値が出るのは、直開きで本当に困ることが出てきたとき。
practice-lab で唯一の手間は「ダウンロードした JSON を `results/` に移す」ことなので、困ったらそこだけを次のどれかで解決すればよい。

* エージェントに「ダウンロードフォルダにある」と言って移してもらう（今のスキルの手順にある）
* ブラウザの File System Access API（Chrome / Edge）で、最初に1回だけ保存先フォルダを選ばせ、以後は直接書き込む
* 必要なときだけ起動する小さなローカルサーバー（例：`lab.py serve`）を**選択肢として**足す。直開きはそのまま残す

## 他のエージェント用スキルの画面はどう作られているか

スキルの中身は基本的に「エージェントへの手順書（Markdown）＋エージェントが実行するスクリプト」。画面が要る場合は、だいたい次の3通り。

1. **静的な HTML を生成して開かせる**（practice-lab の方式）
2. **localhost の開発サーバーを立てる**（Web アプリそのものを作る・確認するスキルに多い）
3. **エージェントの製品側の表示機能を使う**（チャット画面の横に出る成果物など。その製品の中でしか使えない）
