## この章の地図

```
参照の共有（変数は矢印。= は矢印のコピー）
   ├──→ 引数の渡し方（呼び出しも = と同じ）
```

## 参照の共有

### 一言でいうと

Java・C# の class 型の変数、そして Python のすべての変数に入っているのは、**オブジェクトそのものではなく、オブジェクトを指す矢印（参照）**。
`b = a` はオブジェクトをコピーしない。**a の矢印をコピーして、b も同じオブジェクトを指すようにする**だけ。

### 図で見る

```python
a = [1, 2]
b = a
```

```
 変数          オブジェクト
 a ──────┐
         ├──→ [1, 2]      ← オブジェクトは1個だけ
 b ──────┘
```

リストは1個しかない。名前が2つあるだけ。だから b 経由で中身を変えると、a から見ても変わっている。

```python
a = [1, 2]
b = a
b.append(3)
print(a, a is b)   # [1, 2, 3] True
```

`a is b` は「a と b が同じオブジェクトを指しているか」を調べる。True なので、同じ1個のリスト。

### 3つの言語で同じことが起きる

Java（class のオブジェクト）：

```java
class P { int x; }

// main の中
P a = new P();
a.x = 1;
P b = a;            // 矢印のコピー。オブジェクトは増えない
b.x = 5;
System.out.println(a.x + " " + (a == b));   // 5 true
```

C#（class のオブジェクト）：

```csharp
var a = new P { X = 1 };
var b = a;
b.X = 5;
Console.WriteLine($"{a.X} {ReferenceEquals(a, b)}");   // 5 True

class P { public int X; }
```

Java の `a == b`（参照型どうし）、C# の `ReferenceEquals(a, b)`、Python の `a is b` は、どれも「同じオブジェクトか」を調べる道具。迷ったらこれを出力すれば確かめられる。

### オブジェクトを増やすのは `new`（や `[...]`）だけ

**オブジェクトが何個あるかは、`new`（Python ならリストの `[...]` や `P()` の呼び出し）を実行した回数で決まる。** `=` を何回書いても、オブジェクトは1個も増えない。

| コード | オブジェクトの数 |
|---|---|
| `P a = new P(); P b = a;` | 1個 |
| `P a = new P(); P b = new P();` | 2個 |
| `a = [1, 2]; b = a` | 1個 |
| `a = [1, 2]; b = [1, 2]` | 2個（中身が同じでも別物） |

### よくある誤解

- **`ref.assign-copies`**：「オブジェクトを代入すると、中身が丸ごとコピーされる」と思っている → 実際は矢印のコピー。上の Java・C#・Python の例で、b を変えると a も変わる。
- **「class のオブジェクトは矢印だが、リストは代入でコピーされる」**：Python には型による例外は無い。int でも文字列でもリストでも、`=` はいつも矢印のコピー（int や文字列で違いが見えない理由は「不変オブジェクト」の節）。

## 中身を変える操作と、矢印を付け替える操作

### 一言でいうと

変数を使った書き換えには2種類しかない。**指している先の中身を変える**か、**変数の矢印を別のオブジェクトに付け替える**か。どちらなのかは、左辺の形で決まる。

### 見分け方の表

| 書き方 | 種類 | 同じ物を指している他の変数から |
|---|---|---|
| `b.x = 5` / `b.X = 5` | 中身を変える（b が指す先の x を書き換える） | 変化が見える |
| `b.append(3)` / `list.add(3)` | 中身を変える（メソッドがオブジェクトを書き換える） | 変化が見える |
| `b[0] = 9` | 中身を変える（b が指すリストの0番目を書き換える） | 変化が見える |
| `b = new P()` / `b = [9]` | 矢印を付け替える（b という変数だけが変わる） | 変化は見えない |

**左辺が「変数名だけ」なら付け替え、「変数名.何か」「変数名[何か]」なら中身の書き換え**。メソッドの呼び出しは、そのメソッドが中身を変えるものか（`append`）、新しい物を返すものか（文字列の `upper`）で決まる。

### 付け替えの例

```python
a = [1, 2]
b = a
b = [9]            # b の矢印を、新しいリストに付け替える
print(a, b, a is b)   # [1, 2] [9] False
```

```
 b = a のあと          b = [9] のあと
 a ──┐                 a ────→ [1, 2]
     ├─→ [1, 2]
 b ──┘                 b ────→ [9]
```

Java でも同じ。

```java
class P { int x; }

// main の中
P a = new P();
a.x = 1;
P b = a;
b = new P();        // b だけを新しいオブジェクトに付け替える
b.x = 9;            // 新しいほうの x を変える
System.out.println(a.x + " " + b.x);   // 1 9
```

### Python の `+=` と `+` の落とし穴

リストの `+=` は「中身を変える」、`+` は「新しいリストを作る」。だから結果が変わる。

```python
xs = ['x']
ys = xs
ys += ['y']        # 今のリストの中身を伸ばす（extend と同じ）
print(xs)          # ['x', 'y']        ← xs も変わる
ys = ys + ['z']    # 新しいリストを作って、ys を付け替える
print(xs, ys)      # ['x', 'y'] ['x', 'y', 'z']   ← xs は変わらない
```

見た目は似ているが、`ys += ...` は中身の書き換え、`ys = ys + ...` は付け替え。

## 引数の渡し方

### 一言でいうと

メソッドや関数を呼ぶと、**引数の変数に、呼び出し元の矢印がコピーされる**。つまり呼び出しは、`q = p` という代入をしてからメソッドの本体を実行するのと同じ。だから前の節の表がそのまま使える。

- 引数経由で**中身を変える**（`q.x = 9`）→ 呼び出し元にも見える
- 引数を**付け替える**（`q = new P()`）→ 呼び出し元の変数は変わらない

### 両方を並べる

```java
class P { int x = 1; }

// Main クラスの中
static void set(P q) { q.x = 9; }        // 中身を変える
static void reset(P q) {
  q = new P();                           // 付け替える（q だけ）
  q.x = 7;                               // 新しいほうの x を変える
}

// main の中
P p = new P();
set(p);
System.out.println(p.x);   // 9
reset(p);
System.out.println(p.x);   // 9   ← 7 にはならない
```

`reset` の中で起きていること：

| 時点 | p の矢印 | q の矢印 | 元のオブジェクトの x | 新しいオブジェクトの x |
|---|---|---|---|---|
| 呼んだ直後（`q = p` と同じ） | 元 | 元 | 9 | — |
| `q = new P()` のあと | 元 | 新 | 9 | 1 |
| `q.x = 7` のあと | 元 | 新 | 9 | 7 |
| 戻ったあと | 元 | （q は消える） | 9 | （誰も指していない） |

Python も同じ。

```python
def add_zero(xs):
    xs.append(0)      # 中身を変える → 呼び出し元に見える

def replace(xs):
    xs = [0]          # 付け替える → 呼び出し元は変わらない

a = [1]
add_zero(a)
print(a)    # [1, 0]
replace(a)
print(a)    # [1, 0]
```

#### 2回目の `print(a)` が `[0]` にならない理由

`replace` の中の `xs = [0]` は、**`xs` という変数の矢印を付け替えるだけ**で、`a` には何もしない。`replace(a)` を呼んだところから1行ずつ追う。この時点で、a は `add_zero` によって `[1, 0]` になっている。

**① `replace(a)` を呼ぶ** ―― `xs = a` と同じことが起きる（矢印のコピー）

```
 a  ──┐
      ├──→ [1, 0]
 xs ──┘
```

**② `xs = [0]`** ―― 新しいリスト `[0]` を作り、**xs の矢印だけ**をそちらに付け替える

```
 a  ────→ [1, 0]     ← a は何も変わっていない

 xs ────→ [0]        ← xs だけが新しいリストを指す
```

**③ 関数から戻る** ―― xs という変数は消える。`[0]` は誰からも指されなくなり、捨てられる

```
 a  ────→ [1, 0]
```

**④ `print(a)`** ―― a は最初からずっと同じリストを指したままなので、`[1, 0]`

`[0]` と答えたくなるのは、`xs = [0]` を「xs が指しているリストを `[0]` に置き換える」と読んだとき。でも `=` がやるのは「左辺の変数の矢印を、右辺のオブジェクトに向け直す」ことだけで、**矢印の先のリストそのものには触らない**。

a が見ているリストの中身を変えるのは、「変数名.何か」や「変数名[何か]」の形。

| 関数の中の書き方 | 何が起きるか | 呼んだあとの a（呼ぶ前は `[1, 0]`） |
|---|---|---|
| `xs = [0]` | xs の矢印を、新しいリストに付け替える | `[1, 0]`（変わらない） |
| `xs.append(0)` | xs と a が共に指すリストの中身に足す | `[1, 0, 0]` |
| `xs[0] = 0` | 共に指すリストの0番目を書き換える | `[0, 0]` |
| `xs[:] = [0]` | 共に指すリストの中身を全部入れ替える | `[0]` |

関数の中から呼び出し元のリストを `[0]` にしたいなら、`xs[:] = [0]` と書く。これは「矢印の先のリストの中身を全部置き換える」操作なので、a から見ても変わる。

この区別は、上の Java の例とまったく同じ仕組み。Java の `q = new P()` が、Python の `xs = [0]` にあたる。

### 「参照渡し」という言い方に注意

Java や Python を「参照渡し」と説明する本や記事があるが、正確には**「参照を値渡しする」**（矢印のコピーを渡す）。本当の参照渡しなら、引数の付け替えが呼び出し元に届くはず。届かないので、参照渡しではない。

C# には本当の参照渡し（`ref`）がある。`ref` を付けると、変数そのものが渡り、付け替えが呼び出し元に届く。

```csharp
var p = new P();
Reset(ref p);
Console.WriteLine(p.X);   // 7

static void Reset(ref P q)
{
    q = new P();
    q.X = 7;
}

class P { public int X = 1; }
```

Java と Python には `ref` にあたるものは無い。呼び出し元の変数を差し替えたいときは、**新しいオブジェクトを戻り値で返し、呼び出し元で代入する**（`p = reset(p);`）。

### よくある誤解

- **`arg.reassign-affects-caller`**：「メソッドの中で引数に新しいオブジェクトを代入すると、呼び出し元の変数も差し替わる」と思っている → 引数は呼び出し元とは別の変数。付け替えは引数だけに起きる。
- **`arg.mutation-invisible`**：「引数のオブジェクトの中身を変えても、呼び出し元には影響しない」と思っている → 同じオブジェクトを指しているので、中身の変更は見える。

## 戻り値とカプセル化

### 一言でいうと

**戻り値も矢印のコピー**。private なフィールドに入っているミュータブルなオブジェクト（リストなど）をそのまま返すと、受け取った側はクラスの中の**同じオブジェクト**を手にする。`private` も `readonly` / `final` も、それを止められない。

### 穴のあいた getter

```csharp
var c = new Cart();
c.Items.Add("pen");          // 返ってきた矢印の先（Cart の中のリスト）に Add
Console.WriteLine(c.Count);  // 1   ← Cart の中身が外から変わった

class Cart
{
    private readonly List<string> items = new();
    public List<string> Items => items;     // 中のリストへの矢印をそのまま返す
    public int Count => items.Count;
}
```

- `private` が守るのは「`items` というフィールド（変数）に、外から直接触れないこと」だけ
- `readonly` が守るのは「`items` の矢印を付け替えないこと」だけ
- どちらも「矢印の先の中身」は守らない。矢印を外に渡した時点で、中身は外から変えられる

### 守り方

読み取り専用の型で返すと、外から `Add` を呼ぶコードはコンパイルできなくなる。

```csharp
class Cart
{
    private readonly List<string> items = new();
    public IReadOnlyList<string> Items => items.AsReadOnly();   // 読み取り専用の窓を返す
}
// 外で c.Items.Add("pen") と書くと、コンパイルエラー
```

| 言語 | 中身を守って返す書き方 |
|---|---|
| Java | `List.copyOf(items)`（その時点の、変更できないコピー）、`Collections.unmodifiableList(items)`（元を映す読み取り専用の窓） |
| C# | `items.AsReadOnly()`、戻り値の型を `IReadOnlyList<T>` にする |
| Python | `tuple(self._items)` などのコピーを返す（Python に private は無く、`_` は約束） |

### よくある誤解

- **`encap.private-means-safe`**：「フィールドを private にすれば、外から中身を変えられることはない」と思っている → 矢印を返せば、外からその中身を変えられる。

## コピー：浅いコピーと深いコピー

### 一言でいうと

リストをコピーする方法（Python の `list(a)`・`a[:]`・`a.copy()`、Java の `new ArrayList<>(a)`、C# の `new List<T>(a)`）は、**入れ物（リスト）だけを新しく作り、中に入っている矢印はそのままコピーする**。これを**浅いコピー**という。要素のオブジェクトは、元のリストと共有されたまま。

### 図で見る

```python
a = [[1], [2]]
b = list(a)          # 浅いコピー
```

```
 a ──→ [ ● , ● ]          ← 入れ物は別々
         │    │
         ↓    ↓
        [1]  [2]          ← 要素のオブジェクトは共有
         ↑    ↑
         │    │
 b ──→ [ ● , ● ]
```

```python
import copy

a = [[1], [2]]
b = list(a)
b[0].append(9)       # 共有している要素の中身を変える → a からも見える
b.append([3])        # b の入れ物に要素を足す → a の入れ物は別なので見えない
print(a)             # [[1, 9], [2]]
print(b)             # [[1, 9], [2], [3]]
c = copy.deepcopy(a) # 深いコピー：要素のオブジェクトまで全部作り直す
c[0].append(7)
print(a[0], c[0])    # [1, 9] [1, 9, 7]
```

Java でも同じ。

```java
class P { int x = 1; }

// main の中
List<P> a = new ArrayList<>();
a.add(new P());
List<P> b = new ArrayList<>(a);   // 浅いコピー
b.get(0).x = 7;                   // 共有している P の中身を変える
b.add(new P());                   // b の入れ物に足す
System.out.println(a.get(0).x + " " + a.size() + " " + b.size());   // 7 1 2
```

### 有名な落とし穴：`*` で作った2次元の表

```python
row = [0] * 2
grid = [row] * 2               # 同じ row への矢印を2つ並べる（行は1本だけ）
grid[0][0] = 1
print(grid, grid[0] is grid[1])   # [[1, 0], [1, 0]] True
```

`* 2` は「矢印を2つ並べる」で、行を2本作るわけではない。行ごとに作るなら `[[0] * 2 for _ in range(2)]` と書く（ループのたびに新しい行ができる）。

### コピーについてのよくある質問

#### Q1. `b = a` と `b = list(a)` は何が違う？

**`b = a` はリストを作らない。`b = list(a)` は新しいリスト（入れ物）を1個作る。**

- `b = a`：a の矢印をコピーするだけ。リストは1個のまま、名前が2つ
- `b = list(a)`：新しい入れ物を作り、a の入れ物に入っている**矢印を1本ずつ写す**

```python
a = [1, 2]
b = a          # 同じリスト
c = list(a)    # 新しいリスト
print(a is b, a is c)   # True False
b.append(3)    # a と b が共に指すリストに足す
c.append(4)    # c だけのリストに足す
print(a, b, c)          # [1, 2, 3] [1, 2, 3] [1, 2, 4]
```

```
 b = a                     c = list(a)
 a ──┐                     a ──→ [ ● , ● ]
     ├─→ [ ● , ● ]                 │   │
 b ──┘     │   │                   1   2      ← 要素は共有
           1   2                   │   │
                           c ──→ [ ● , ● ]    ← 入れ物は別
```

`b.append(3)` と `c.append(4)` のあと（`print(a, b, c)` の時点）：

```
 a ──┐
     ├──→ [ ● , ● , ● ]      ← a と b の入れ物（1個）に 3 が増えた
 b ──┘      │   │   │
            ↓   ↓   ↓
            1   2   3
            ↑   ↑
            │   │
 c ──────→ [ ● , ● , ● ]     ← c の入れ物にだけ 4 が増えた
                    │
                    ↓
                    4
```

- `b.append(3)` は、a と b が共に指す入れ物に 3 への矢印を足した → a からも b からも `[1, 2, 3]`
- `c.append(4)` は、c だけの入れ物に 4 への矢印を足した → c は `[1, 2, 4]`。a の入れ物には何も起きない
- 1 と 2 は、今も a（＝b）の入れ物と c の入れ物の両方から指されている（共有）。int は不変なので、共有していても問題は起きない

#### Q2. 浅いコピーは二重リストだけの話？ `a = [1, 2]` は対象外？

**対象外ではない。`list(a)` は `a = [1, 2]` に対しても浅いコピー**（入れ物だけ新しくし、要素の矢印は写す）。実際、コピーした直後は要素の 1 も同じオブジェクトを指している。

```python
a = [1, 2]
c = list(a)
print(c[0] is a[0])   # True    ← 要素の 1 は共有されている
c[0] = 100            # c の入れ物の0番目の矢印を付け替える
print(a, c)           # [1, 2] [100, 2]
```

それでも困らないのは、**要素が int（不変）だから**。int には中身を変える方法が無いので、共有していても誰も中身を変えられない。`c[0] = 100` のような操作は、c の入れ物の矢印を付け替えるだけで、a には届かない。

つまり浅いコピーの「共有」が問題になるのは、**要素がミュータブル（リスト・辞書・自作クラスのオブジェクトなど）で、その要素の中身を変えたとき**だけ。二重リストはその典型例なので、説明に使っている。

| 要素の種類 | 浅いコピーで困るか |
|---|---|
| int・文字列などの不変オブジェクト | 困らない（完全なコピーと同じように振る舞う） |
| リスト・辞書・自作クラスのオブジェクト | 困る（要素の中身を変えると、元にも見える） |

#### Q3. `b[0].append(9)` と `b.append([3])` で、なぜ結果が変わる？ `[0]` は場所を指定しているだけでは？

**`[0]` は場所の指定で合っている。** ただし正確には「**b の入れ物の0番目に入っている矢印をたどって、その先のオブジェクトに行く**」という意味。たどった先が共有されている要素なので、そこで何かをすると元にも見える。

規則は1つ。**式を左から読み、`[ ]` や `.` のたびに矢印を1本たどる。最後の操作は、たどり着いたオブジェクトに対して行われる。**

| 書き方 | たどり着く先 | 何が変わるか | a に見えるか |
|---|---|---|---|
| `b.append([3])` | b の入れ物 | b の入れ物に要素が増える | 見えない（入れ物は別） |
| `b[0].append(9)` | b の入れ物 → 0番目の矢印 → 内側のリスト | 内側のリストに 9 が増える | 見える（内側のリストは共有） |
| `b[1] = [100]` | b の入れ物の1番目の**矢印そのもの** | その矢印を新しいリストに付け替える | 見えない（付け替えたのは b の入れ物の矢印） |
| `b[1].append(5)`（付け替えたあと） | 新しい `[100]` | `[100]` に 5 が増える | 見えない（もう共有していない） |

```python
a = [[1], [2]]
b = list(a)
b.append([3])     # b の入れ物に足す
b[0].append(9)    # 共有している内側のリスト [1] に足す
b[1] = [100]      # b の入れ物の1番目の矢印を、新しいリストに付け替える
b[1].append(5)    # 新しいリストに足す（a とは無関係）
print(a)          # [[1, 9], [2]]
print(b)          # [[1, 9], [100, 5], [3]]
```

見分けるコツ：

- `b[0] = ...`（`[ ]` の直後が `=`）は、**入れ物の矢印の付け替え**。元には見えない
- `b[0].何か(...)` や `b[0][0] = ...`（`[ ]` の先でさらに操作）は、**矢印の先のオブジェクトへの操作**。共有していれば元にも見える

これは「中身を変える操作と、矢印を付け替える操作」の節の規則を、1段深いところに当てはめているだけ。

#### Q4. 深いコピーは、`b = [[1], [2]]` と最初から作り直すのと同じ？

**結果は同じと考えてよい。** 深いコピー（`copy.deepcopy`）は、要素の中にあるオブジェクトまで全部新しく作るので、元とは1つもオブジェクトを共有しない。リテラルで書き直したのと同じ状態になる。

```python
import copy

a = [[1], [2]]
c = copy.deepcopy(a)      # 深いコピー
d = [[1], [2]]            # 最初から作り直す
print(c == a, c is a, c[0] is a[0])   # True False False
print(d == a, d is a, d[0] is a[0])   # True False False
```

3つのやり方を並べるとこうなる。

| | 入れ物 | 内側のリスト（ミュータブルな要素） |
|---|---|---|
| `b = a` | 共有 | 共有 |
| `b = list(a)`（浅いコピー） | 新しい | 共有 |
| `b = copy.deepcopy(a)`（深いコピー） | 新しい | 新しい |
| `b = [[1], [2]]`（作り直す） | 新しい | 新しい |

違いは、深いコピーは「今の a がどんな中身でも」同じ形に作り直してくれること。リテラルで書くには、中身を知っていなければならない。

`a = [1, 2]` のように要素が不変なら、浅いコピー・深いコピー・作り直しのどれでも、使っていて違いは出ない（Q2）。

#### Q5. Java の `new ArrayList<>(a)` は丸ごとコピーだと思っていた。浅いコピーなの？

**半分は合っている。** `new ArrayList<>(a)` は**新しいリストを作る**ので、リストへの追加・削除は元に影響しない（下の出力で、a の要素数は 1、b は 2）。その意味では確かにコピー。

ただし中に入っている P のオブジェクトは作り直されず、**矢印が写されるだけ**。だから「リストの層はコピー、要素の層は共有」で、これを浅いコピーと呼ぶ。

```java
class P { int x = 1; }

// main の中
List<P> a = new ArrayList<>();
a.add(new P());
List<P> b = new ArrayList<>(a);   // リストは新しい。P は共有
b.get(0).x = 7;                   // 共有している P の中身を変える → a からも見える
b.add(new P());                   // b のリストに足す → a のリストは別なので見えない
System.out.println(a.get(0).x + " " + a.size() + " " + b.size());   // 7 1 2
```

Java には `copy.deepcopy` にあたる汎用の道具が無い。要素まで別物にしたいなら、**要素を1つずつ作り直して**新しいリストに入れる。

```java
class P {
  int x = 1;
  P copy() { P p = new P(); p.x = x; return p; }   // 自分と同じ中身の、新しい P を返す
}

// main の中
List<P> a = new ArrayList<>();
a.add(new P());
List<P> b = new ArrayList<>();
for (P p : a) b.add(p.copy());   // 要素ごとに新しい P を作る
b.get(0).x = 7;
System.out.println(a.get(0).x + " " + b.get(0).x);   // 1 7
```

C# の `new List<P>(a)`、Python の `list(a)` も同じく浅いコピー。「コピー」と名の付く道具の多くは浅いコピーだと思っておくと安全。

#### Q6. `[0] * 2` や `[row] * 2` は、そもそも何の書き方？

**リストに `* n` を掛けると、要素を n 回くり返したリストができる。** 文字列にも使える。

```python
print([0] * 3, [1, 2] * 2, 'ab' * 3)   # [0, 0, 0] [1, 2, 1, 2] ababab
```

大事なのは、くり返されるのが**要素の矢印**であって、要素のオブジェクトが増えるわけではないこと。

- `[0] * 2`：0 への矢印を2本並べる。0 は不変なので困らない（Q2 と同じ理由）

```python
row = [0] * 2
print(row[0] is row[1])   # True    ← 同じ 0 を指している
row[0] = 1                # row の入れ物の0番目の矢印を付け替えるだけ
print(row)                # [1, 0]
```

- `[row] * 2`：**row というリストへの矢印を2本並べる**。行のリストは1本しかない。だから `grid[0][0] = 1`（矢印をたどった先の行の中身を変える）は、grid[1] からも見える

```
 grid ──→ [ ● , ● ]
            │   │
            └─┬─┘
              ↓
 row  ────→ [ 0 , 0 ]      ← 行は1本だけ
```

行を本当に2本作るには、ループで毎回新しい行を作る。

```python
grid = [[0] * 2 for _ in range(2)]   # ループのたびに [0] * 2 が実行され、新しい行ができる
grid[0][0] = 1
print(grid, grid[0] is grid[1])      # [[1, 0], [0, 0]] False
```

`[0] * 2` を「0 という値を2回書いたもの」、`[row] * 2` を「row の中身を2回書いたもの」と読むと間違える。**`* n` は矢印を n 本並べる**と読む。

### よくある誤解

- **`ref.copy-is-deep`**：「リストや配列をコピーすれば、中のオブジェクトも別物になる」と思っている → コピーされるのは入れ物だけ。要素は共有される。

## 不変オブジェクト

### 一言でいうと

文字列や数値のように、**作ったあと中身を変える方法が無いオブジェクト**を不変（イミュータブル）という。不変オブジェクトは、矢印をいくら共有しても困らない。誰も中身を変えられないから。

### なぜ文字列や数値では「共有」が見えないのか

```python
s = 'abc'
t = s              # t も同じ 'abc' を指す
t = t.upper()      # upper は新しい文字列を返す → t を付け替える
print(s, t)        # abc ABC

n = 1
m = n
m += 1             # int に「中身を変える」操作は無い。新しい int（2）に付け替える
print(n, m)        # 1 2
```

文字列にも数値にも、中身を書き換えるメソッドが1つも無い。だから「中身を変える」ことができず、変えたように見える操作は全部「新しいオブジェクトを作って付け替える」になる。その結果、矢印の仕組みは同じでも、リストのような共有の問題が起きない。

文字列の変換メソッドを呼んだだけで戻り値を受け取らないと、何も変わらない。

| 書き方 | s は |
|---|---|
| `s.toUpperCase();`（Java）/ `s.ToUpper();`（C#）/ `s.upper()`（Python） | 変わらない（新しい文字列が作られて捨てられる） |
| `s = s.toUpperCase();` | 新しい文字列に付け替わる |

### `final` / `readonly` は「不変」ではない

`final`（Java）や `readonly`（C#）が禁止するのは、**変数の付け替え**だけ。指している先の中身は変えられる。

| | 付け替えられる | 中身を変えられる |
|---|---|---|
| 普通の変数 ＋ ArrayList | できる | できる |
| `final` ＋ ArrayList | できない | **できる** |
| 普通の変数 ＋ `List.of(...)` | できる | できない |
| `final` ＋ `List.of(...)` | できない | できない |

「誰にも変えられない」にしたいなら、`final` と不変オブジェクトの両方をそろえる。

### よくある誤解

- **`immut.method-mutates`**：「文字列の変換メソッドを呼べば、その変数の文字列が書き換わる」と思っている → 文字列は不変。結果は戻り値で受け取る。
- **`immut.final-freezes`**：「final / readonly を付ければ、オブジェクトの中身も変えられなくなる」と思っている → 禁止されるのは再代入だけ。

## 値型と参照型

### 一言でいうと

ここまでの「変数は矢印」には例外がある。**値型**の変数は、矢印ではなく**中身そのもの**を持つ。値型の代入は、中身のコピーになる。

| 言語 | 値型（代入で中身がコピーされる） | 参照型（代入で矢印がコピーされる） |
|---|---|---|
| Java | `int` `double` `boolean` などの基本型 | クラス、配列、`String`、`Integer` など、基本型以外すべて |
| C# | `int` `double` などと、**`struct`** | `class`、配列、`string` |
| Python | なし | すべて（int も文字列もリストも） |
| C++ | **クラスのオブジェクトも含めて、ほぼすべて**（ポインタや参照 `&` を使ったときだけ共有） | ポインタ・参照で扱うとき |

### C# の struct と class を並べる

同じ形のコードでも、`struct` か `class` かで結果が逆になる。

```csharp
var a = new PS { X = 1 };
var b = a;        // struct：中身ごとコピー
b.X = 5;
var c = new PC { X = 1 };
var d = c;        // class：矢印のコピー
d.X = 5;
Console.WriteLine($"{a.X} {c.X}");   // 1 5

struct PS { public int X; }
class PC { public int X; }
```

### Java の基本型と配列を並べる

```java
// main の中
int a = 1;
int b = a;        // 基本型：値のコピー
b = 5;
int[] xs = {1};
int[] ys = xs;    // 配列は参照型：矢印のコピー
ys[0] = 5;
System.out.println(a + " " + xs[0]);   // 1 5
```

### C++ について

C++ ではクラスのオブジェクトも、代入すると中身ごとコピーされる（`P b = a;` で別のオブジェクトができる）。共有したいときは、参照（`P& b = a;`）かポインタ（`P* b = &a;`）を明示する。Java・C#・Python と逆なので、C++ のコードを読むときは「`&` や `*` が無ければコピー」と切り替える。

### よくある誤解

- **`val.all-reference`**：「どの言語でも、オブジェクトの代入は参照の共有になる」と思っている → C# の struct と C++ のオブジェクトは、代入でコピーされる。

## 同じオブジェクトか、中身が等しいか

### 一言でいうと

「同じオブジェクトを指しているか（同一性）」と「中身が等しいか（等価性）」は別の質問。

```python
a = [1, 2]
b = a
c = [1, 2]
print(a == b, a is b)   # True True    ← 同じオブジェクト
print(a == c, a is c)   # True False   ← 中身は等しいが、別のオブジェクト
```

```java
class P {
  int x;
  P(int x) { this.x = x; }
}

// main の中
P a = new P(1);
P b = a;
P c = new P(1);
System.out.println((a == b) + " " + (a == c));             // true false
String s = new String("hi");
System.out.println((s == "hi") + " " + s.equals("hi"));    // false true
```

| 言語 | 同じオブジェクトか | 中身が等しいか |
|---|---|---|
| Java | `==`（参照型どうし） | `equals`（クラスで定義していれば） |
| C# | `ReferenceEquals(a, b)` | `Equals`、`==`（`string` などは中身の比較に定義されている） |
| Python | `is` | `==` |

Java の文字列を `==` で比べてはいけないのは、`==` が「同じオブジェクトか」を調べるから。等価性の詳しい話（`equals` と `hashCode` をそろえる理由など）は次の章で扱う。

## 応用：デフォルト引数の落とし穴（Python）

ここまでの知識で、Python の有名な落とし穴が説明できる。

```python
def add(x, items=[]):
    items.append(x)
    return items

print(add(1))   # [1]
print(add(2))   # [1, 2]   ← 前の呼び出しの 1 が残っている
```

既定値の `[]` は、`def` の行が実行されたときに**1回だけ**作られる。引数を省略して呼ぶたびに、`items` にはその同じリストへの矢印がコピーされる。`append` は中身を変える操作なので、呼び出しをまたいで溜まっていく。

直すときは、既定値を `None`（不変）にして、関数の中で毎回新しいリストを作る。

```python
def add(x, items=None):
    if items is None:
        items = []      # 呼ぶたびに新しいリストを作る
    items.append(x)
    return items
```

見分けるポイントは、**`[]` がどこに書いてあるか**。`def` の行なら1回だけ作られて共有、関数の本体の中なら呼ぶたびに新しく作られる。

## まとめ：この章の決まりは3つだけ

1. **変数（値型以外）に入っているのは矢印。** `=`・引数の受け渡し・`return` は、どれも矢印のコピー。オブジェクトを増やすのは `new` などの生成だけ
2. **書き換えは2種類。** 左辺が「変数名だけ」なら付け替え（他の変数には見えない）、「変数名.何か」「変数名[何か]」や中身を変えるメソッドなら中身の書き換え（同じ物を指す全員に見える）
3. **例外は値型。** Java の基本型、C# の struct、C++ のオブジェクトは、代入で中身がコピーされる

章の最初の4つの問いの答え：

| 問い | 答え | どの決まりで |
|---|---|---|
| `b = a; b.append(3)` のあと a は？ | `[1, 2, 3]` | 1（同じリスト）＋ 2（append は中身の書き換え） |
| `reset(p)` のあと p.x は？ | 1 のまま | 1（引数は矢印のコピー）＋ 2（`q = new P()` は付け替え） |
| private readonly なのに外から Add できるのは？ | getter が中のリストへの矢印を返しているから | 1（戻り値も矢印のコピー） |
| `ys += ['y']`、`ys = ys + ['z']` のあと xs は？ | `['x', 'y']`（+= は変わる、+ は変わらない） | 2（+= は中身、+ は新しいリストに付け替え） |

## 理解度チェック

### 言える

1. `P b = a;`（Java、P はクラス）を実行すると、オブジェクトは何個になる？ `P b = new P();` なら？

### 説明できる

2. 次のコードで、2回目の出力が 7 にならない理由を、「矢印」という言葉を使って説明する。

```java
class P { int x = 1; }

// Main クラスの中
static void reset(P q) {
  q = new P();
  q.x = 7;
}

// main の中
P p = new P();
reset(p);
System.out.println(p.x);
```

3. 次の2つのコードで、xs の結果が違う理由を説明する。

```python
xs = [1]
ys = xs
ys.append(2)
print(xs)
```

```python
xs = [1]
ys = xs
ys = ys + [2]
print(xs)
```

### 使える

4. 次の Java のクラスは、外から `getTags().add(...)` で中身を増やせてしまう。中身を守るように `getTags` を書き直す。

```java
class Article {
  private final List<String> tags = new ArrayList<>();
  List<String> getTags() { return tags; }
}
```

5. 3行3列の0の表を Python で作りたい。`[[0] * 3] * 3` ではなく、どう書く？ その理由も一言で。

---

## 理解度チェックの答え

1. `P b = a;` では1個（矢印が2本になるだけ）。`P b = new P();` なら、a のオブジェクトと合わせて2個。
2. `reset(p)` を呼ぶと、引数 q に p の矢印がコピーされる。`q = new P()` は q の矢印を新しいオブジェクトに付け替えるだけで、p の矢印は元のオブジェクトを指したまま。`q.x = 7` が変えたのは新しいオブジェクトの x なので、p.x は 1 のまま。出力は `1`。
3. 1つめの `append` は、xs と ys が共に指しているリストの中身を変えるので、xs から見ても `[1, 2]`。2つめの `ys + [2]` は新しいリストを作り、ys をそちらに付け替えるだけなので、xs は `[1]` のまま。
4. 例：`List<String> getTags() { return List.copyOf(tags); }`（変更できないコピーを返す）。あとから Article の中で追加されたタグも見せたいなら、`Collections.unmodifiableList(tags)`（読み取り専用の窓）。
5. `[[0] * 3 for _ in range(3)]`。`[[0] * 3] * 3` は同じ行への矢印を3つ並べるだけなので、1マス変えると全部の行が変わる。内包表記ならループのたびに新しい行ができる。
