## 書き換え先の読み分け

### 一言でいうと

**何が書き換わるかは、書き方（左辺の形）だけで決まる。** 覚える形は4つしかない。

| 書き方 | 書き換わるもの | 新しいオブジェクトは |
|---|---|---|
| `x = 式` | 名札 `x` の**貼り先だけ**。オブジェクトは何も変わらない | 右辺の式が作るなら、できる |
| `obj.x = 式` | **ドットの左の `obj`** というオブジェクトの、属性 `x` | 右辺の式が作るなら、できる |
| `obj[k] = 式` | **`obj`** というオブジェクトの、`k` 番目（キー `k`）の中身 | 右辺の式が作るなら、できる |
| `obj.メソッド(...)`（`append` など） | メソッドによる。`append`、`extend`、`insert`、`sort`、`update`、`pop` は **`obj` の中身** | できない |

そして、**新しいオブジェクトができる書き方**も決まっている。

| 新しいオブジェクトができる | できない（共有になる） |
|---|---|
| `[...]`、`{...}`、`(...)`（書いた瞬間に作る） | `y = x`（名札が増えるだけ） |
| `x + y`、`x * 2`（計算の結果） | 関数に渡す `f(x)` |
| `list(x)`、`dict(x)`、`x.copy()` | `return x` |
| `クラス名(...)`（インスタンスを作る） | `for t in tools:` の `t`（リストの要素に名札を貼るだけ） |

c2 のメモ「共有するタイミングと自分だけの参照先を持つタイミング」の答えは、この表そのものだ。**右の列の書き方をしたら共有、左の列の書き方をしたら自分だけのもの。** 本当に書き方だけで決まる。

### なぜ必要か・どこで効くか

第1章の「名前と参照」、第2章の「属性の探索」は、どちらもこの表の上に立っている。

- `b = a` のあと `b.append(1)` で `a` が変わる → `=` は名札だけ、`append` は中身を変える
- `c1.retries = 5` で `c2.retries` が変わらない → `obj.x =` は**ドットの左のオブジェクト**（`c1`）だけを書き換える

### 本体

#### トレース表の書き方

1行実行するたびに、「名札がどこに貼られているか」と「オブジェクトの中身」を書く。オブジェクトには ①②③ と番号を付ける。

```python
a = [1]          # 1行目
b = a            # 2行目
b = b + [2]      # 3行目
b.append(3)      # 4行目
print(a)         # 5行目
```

| 行 | 書き方の種類 | 名札 | オブジェクト |
|---|---|---|---|
| 1 | `x = [...]`（新しく作る） | a→① | ① `[1]` |
| 2 | `x = y`（名札を増やすだけ） | a→①、b→① | ① `[1]` |
| 3 | `x = 計算`（新しく作る） | a→①、**b→②** | ① `[1]`、② `[1, 2]` |
| 4 | `x.append`（中身を変える） | a→①、b→② | ① `[1]`、② `[1, 2, 3]` |
| 5 | | | `a` は ① なので `[1]` |

3行目が分かれ目だ。`b + [2]` は**計算の結果**なので、新しいオブジェクト②ができる。`b` の名札は②に移り、①はもう `a` だけのものになる。

#### 属性の書き換えもトレースできる

c5 をトレースする。クラスもオブジェクトなので、表に並べる。

```python
class Config:          # 1行目
    retries = 3
c1 = Config()          # 3行目
c2 = Config()          # 4行目
c1.retries = 5         # 5行目
Config.retries = 10    # 6行目
print(c1.retries, c2.retries)
```

| 行 | 書き方 | Config の属性 | c1 の属性 | c2 の属性 |
|---|---|---|---|---|
| 1-2 | クラスを作る | `retries=3` | | |
| 3 | `クラス名()`（新しく作る） | `retries=3` | （空） | |
| 4 | `クラス名()`（新しく作る） | `retries=3` | （空） | （空） |
| 5 | **`c1.` の書き換え** | `retries=3` | `retries=5` | （空） |
| 6 | **`Config.` の書き換え** | `retries=10` | `retries=5` | （空） |

最後の行で読むとき：
- `c1.retries` → `c1` に `retries` がある → **5**
- `c2.retries` → `c2` は空なので、クラスへ探しに行く（第2章「属性の探索」）→ **10**

c5 のメモ「どれが属性を操作していてどれがインスタンスを操作してるのか」の答えは、**ドットの左に書いてある名前**だ。5行目はドットの左が `c1` なので `c1` の列が変わる。6行目は `Config` なので `Config` の列が変わる。それ以外の列は変わらない。

#### 書いているのか、読んでいるのか

同じ `c1.retries` でも、`=` の左にあれば「書く」、それ以外の場所にあれば「読む」だ。

| 書き方 | 書く／読む | 行き先 |
|---|---|---|
| `c1.retries = 5` | 書く | いつも `c1` 自身 |
| `print(c1.retries)` | 読む | `c1` → クラス → 親クラス の順に探す |
| `c1.retries += 1` | **読んでから書く** | 読むのは探索、書くのは `c1` 自身 |
| `c1.items.append(1)` | `c1.items` を**読み**、その先のリストの中身を変える | `c1` に属性は作られない |

最後の2行が第2章の q1 と Counter の違いだった。

### よくある誤解

**`syntax.target-blind`：代入の左辺の形（名前・属性・要素）によって、書き換わる相手が変わることを意識していない**

- 思い込み：`=` があれば、何かが「上書き」される。何が上書きされるかはあまり気にしていない
- 実際：`x =` は名札 `x` だけ、`obj.x =` はドットの左の `obj`、`obj[k] =` は `obj` の中身を変える
- 確かめ方：トレース表を書き、各行で変わる列が1つだけであることを確かめる

### 理解度チェック

- **言える**：`x =`、`obj.x =`、`obj[k] =`、`obj.append(...)` が、それぞれ何を変えるか
- **説明できる**：`y = x` と `y = x + []` の違いを、「新しいオブジェクトができるか」で説明する
- **使える**：次のコードをトレース表にして、最後の出力を求める

  ```python
  class Box:
      items = []
  b1 = Box()
  b2 = Box()
  b1.items.append("x")
  b1.items = ["y"]
  print(b2.items, b1.items, Box.items)
  ```

## 辞書の基本操作

### 一言でいうと

辞書は「キー → 値」の対応表だ。操作は3つ覚えればよい。

| 書き方 | 意味 | キーが**無い**とき |
|---|---|---|
| `d[k]`（読む） | キー `k` の値を取り出す | **`KeyError`** |
| `d[k] = v`（書く） | キー `k` の値を `v` にする | **新しく追加する**（エラーにならない） |
| `d.get(k, 既定値)`（安全に読む） | キー `k` の値を取り出す | **既定値を返す**（エラーにならない） |

**エラーになるのは「無いキーを `d[k]` で読んだとき」だけ**だ。書くときはエラーにならない。

### なぜ必要か・どこで効くか

c4 で「無いキーへの代入はエラー」と考えて間違えた。読むときのルール（`KeyError`）と、書くときのルール（追加される）が混ざっていた。
LLMアプリでは、`{"role": ..., "content": ...}` のメッセージ、設定、ツールの引数、集計など、辞書がいたるところに出てくる。

### 本体

#### 3つの操作を試す

```python
d = {}
d["a"] = 1          # 無いキーに書く → 追加される
print(d)            # {'a': 1}

print(d["a"])       # 1
print(d.get("b", 0))  # 0   ← 無いキーでも既定値が返る
print(d.get("b"))   # None ← 既定値を省くと None
print(d["b"])       # KeyError: 'b'
```

#### 回数を数える書き方

`d[k] = d.get(k, 0) + 1` は、辞書で回数を数えるときの定番だ。右辺から読む。

1. `d.get(k, 0)`：今までの回数を読む。まだ無ければ 0
2. `+ 1`：1足す
3. `d[k] = ...`：その結果を書く。まだ無ければ追加される

```python
counts = {}
for w in ["a", "b", "a"]:
    counts[w] = counts.get(w, 0) + 1
```

| 繰り返し | `w` | `counts.get(w, 0)` | 書いたあとの `counts` |
|---|---|---|---|
| 1回目 | `"a"` | 0（無い） | `{'a': 1}` |
| 2回目 | `"b"` | 0（無い） | `{'a': 1, 'b': 1}` |
| 3回目 | `"a"` | 1 | `{'a': 2, 'b': 1}` |

#### キーがあるかを確かめる、全部を回す

```python
if "a" in counts:              # キーがあるか
    print("ある")

for key, value in counts.items():   # キーと値を順に取り出す
    print(key, value)
```

#### 関数の既定値に `{}` は書ける

c4 では「既定値に `{}` は書けない」とも考えた。**関数では書ける**。書けてしまうから罠になる（第1章「デフォルト引数」）。

```python
def count_event(event, store={}):   # エラーにならない。でも store は全呼び出しで共有される
    ...
```

エラーにして止めてくれるのは、**dataclass のフィールド**だけだ。第1章でこの話をしたので、混ざってしまったのだと思う。

| 場所 | `[]` や `{}` を既定値に書くと |
|---|---|
| 関数の引数 `def f(x={})` | 書ける。全呼び出しで共有される（罠） |
| dataclass のフィールド `x: dict = {}` | `ValueError` で止まる。`field(default_factory=dict)` と書く |

### よくある誤解

**`dict.assign-missing-key-error`：辞書にまだ無いキーへ代入すると、エラーになると思っている**

- 思い込み：`d["new"] = 1` は、`"new"` が無いので `KeyError`
- 実際：エラーになるのは無いキーを読んだとき（`d[k]`）だけ。`d[k] = v` はキーが無ければ追加する
- 確かめるコード：`d = {}; d["x"] = 1; print(d)`

**`def.mutable-default-error`：関数のデフォルト引数にミュータブルな値（`{}` や `[]`）を書くと、エラーになると思っている**

- 思い込み：`def f(x={})` は書いた時点でエラー
- 実際：関数では書けてしまう。エラーにして止めてくれるのは dataclass のフィールドだけ
- 確かめるコード：`def f(x={}): return x` を実行し、エラーにならないことを見る

### 理解度チェック

- **言える**：`d[k]` を読むときと `d[k] = v` と書くときで、キーが無い場合にそれぞれどうなるか
- **説明できる**：`d.get(k, 0) + 1` が「回数を数える」書き方になる理由
- **使える**：c4 のコードをトレース表にして、2回目の呼び出しの結果を求める

## メソッド呼び出し

### 一言でいうと

`obj.m(x)` と書くと、Python は `クラス.m(obj, x)` に書き換えて呼ぶ。**`self` には `obj` が自動で入る。**
だから、**呼び出し側で数える引数は、`self` を除いた分**だ。

| 定義 | 呼び出し側で渡す引数 |
|---|---|
| `def search(self, q):` | `w.search("python")` ← **1個**（`self` は自動） |
| `def run(self, task, retries):` | `a.run("plan", 3)` ← **2個** |
| `def describe(self):` | `a.describe()` ← **0個** |

### なぜ必要か・どこで効くか

c7 では「呼び出しの `t.search(query)` に `self` が無いので、`def search(self, q)` と合わない」と考えた。前回の q2 では「`planner.remember(...)` は `Agent.remember(planner, ...)` と同じ」を選べていた。でも、それが**この数え方のルール**のことだとは、つながっていなかった。
メソッドを1つ呼ぶたびに引数を数え間違えると、どのコードも「エラーになるはず」に見えてしまう。

### 本体

#### 書き換えをトレースする

```python
class WebSearch:
    def search(self, q):
        return "web: " + q

w = WebSearch()
print(w.search("python"))
```

`w.search("python")` を、Python がどう処理するかを1段ずつ書く。

| 段 | 何が起きるか |
|---|---|
| 1 | `w.search` を探す。`w` には無いので、クラス `WebSearch` で `search` が見つかる（第2章「属性の探索」） |
| 2 | インスタンス `w` から取り出したので、「`w` をセットにしたメソッド」になる |
| 3 | 呼ぶと、`WebSearch.search(w, "python")` として実行される |
| 4 | 定義の `self` に `w`、`q` に `"python"` が入る。2個と2個で**数が合う** |
| 5 | `"web: " + "python"` で `"web: python"` が返る |

#### わざと間違えて、エラーメッセージで確かめる

```python
w.search(w, "python")
# TypeError: WebSearch.search() takes 2 positional arguments but 3 were given
```

`self` を自分で渡すと、自動で入る `w` と合わせて**3個**になる。定義は2個しか受け取れないのでエラーだ。
エラーメッセージの数（`takes 2`、`3 were given`）は、**`self` を含めて数えた数**だ。これを知っていると、引数のエラーが一瞬で読める。

#### 1行で書いた定義を読む

c7 には、こういう書き方が出てきた。

```python
class WebSearch:
    def search(self, q): return f"web: {q}"
```

これは次の2行と**まったく同じ**だ。中身が1文だけのとき、`:` の後ろに続けて書ける。

```python
class WebSearch:
    def search(self, q):
        return f"web: {q}"
```

`f"web: {q}"` は**f文字列**で、`{}` の中の式の値を埋め込む。`q` が `"python"` なら `"web: python"` になる。

#### 内包表記を読む

c7 の `run_all` は**内包表記**という書き方を使っていた。

```python
def run_all(tools, query):
    return [t.search(query) for t in tools]
```

これは次と同じだ。

```python
def run_all(tools, query):
    results = []
    for t in tools:                       # tools の要素に、順に t という名札を貼る
        results.append(t.search(query))   # t の search を呼び、結果をリストに足す
    return results
```

読み方は「**`for t in tools` の部分を先に読み、それぞれの `t` について左側の式を計算して、リストに集める**」だ。

#### ダックタイピングをトレースする

ここまでの読み方がそろうと、c7 はトレースだけで解ける。

```python
run_all([WebSearch(), DocSearch()], "x")
```

| 繰り返し | `t` | `t.search` を探す | 呼び出しの書き換え | 結果 |
|---|---|---|---|---|
| 1回目 | WebSearch のインスタンス | `WebSearch` で見つかる | `WebSearch.search(t, "x")` | `"web: x"` |
| 2回目 | DocSearch のインスタンス | `DocSearch` で見つかる | `DocSearch.search(t, "x")` | `"doc: x"` |

どこにも「`t` が何のクラスか」を確かめる段は無い。**探して見つかれば呼ぶ、それだけ**。これがダックタイピングの正体だ。
`Calculator` を入れると、1段目の「`search` を探す」で見つからず、`AttributeError` になる。

### よくある誤解

**`self.not-auto-passed`：`obj.m(x)` と呼ぶとき `self` に当たる引数が渡されないので、`def m(self, x)` とは引数の数が合わないと思っている**

- 思い込み：定義に `self, q` の2つがあるのに、呼び出しは `q` の1つだけ。だから合わない
- 実際：`obj.m(x)` は `クラス.m(obj, x)` に書き換えられ、`self` には `obj` が自動で入る
- 確かめるコード：上の `w.search("python")` と `w.search(w, "python")` を両方実行し、後者だけがエラーになることを見る

### 理解度チェック

- **言える**：`def run(self, task, retries):` を呼ぶとき、呼び出し側で渡す引数はいくつか
- **説明できる**：`takes 2 positional arguments but 3 were given` の「3」は、何と何と何か
- **使える**：c7 の `run_all` を、内包表記を使わない形に書き直し、`[WebSearch(), DocSearch()]` を渡したときの動きをトレース表にする

## 理解度チェックの答え

### 書き換え先の読み分け

- **言える**：`x =` は名札 `x` の貼り先だけ。`obj.x =` は `obj` の属性 `x`。`obj[k] =` は `obj` の `k` 番目の中身。`obj.append(...)` は `obj` の中身
- **説明できる**：`y = x` は名札が増えるだけなので共有になる。`y = x + []` は計算の結果として新しいリストができるので、自分だけのものになる
- **使える**：`['x'] ['y'] ['x']`

  | 行 | Box | b1 | b2 | リスト |
  |---|---|---|---|---|
  | クラスを作る | items→① | | | ① `[]` |
  | `b1 = Box()`、`b2 = Box()` | items→① | （空） | （空） | ① `[]` |
  | `b1.items.append("x")`：`b1.items` を読む（探索で①）→ ①の中身を変える | items→① | （空） | （空） | ① `['x']` |
  | `b1.items = ["y"]`：`b1.` の書き換え。新しいリスト② | items→① | items→② | （空） | ① `['x']`、② `['y']` |

  `b2.items` は探索で①、`b1.items` は②、`Box.items` は①

### 辞書の基本操作

- **言える**：読む `d[k]` は `KeyError`。書く `d[k] = v` は追加される
- **説明できる**：`d.get(k, 0)` は今までの回数（無ければ 0）を読み、`+ 1` して、`d[k] =` で書き戻す。無いキーでもエラーにならずに 1 から数え始められる
- **使える**：上の「入口の問題をもう一度」の c4 の表のとおり

### メソッド呼び出し

- **言える**：2個（`task` と `retries`）
- **説明できる**：自動で入る `obj`（`self` の分）と、自分で渡した2個
- **使える**：

  ```python
  def run_all(tools, query):
      results = []
      for t in tools:
          results.append(t.search(query))
      return results
  ```

  | 繰り返し | `t` | 見つかる `search` | 書き換え | `results` |
  |---|---|---|---|---|
  | 1回目 | WebSearch のインスタンス | `WebSearch.search` | `WebSearch.search(t, "x")` | `['web: x']` |
  | 2回目 | DocSearch のインスタンス | `DocSearch.search` | `DocSearch.search(t, "x")` | `['web: x', 'doc: x']` |
